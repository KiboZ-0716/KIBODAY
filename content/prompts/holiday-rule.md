# 非工作日跳过与搜索窗口扩展（2026-11-13 读者要求）

适用：`K!B0 每日情报` 08:00、`日报兜底补跑` 08:50、`站点同步` 09:00 三个定时任务。
判断脚本 `scripts/workday.mjs`，日历 `content/holidays.json`（周末默认非工作日 + 法定放假日区间 + 调休补班日）。

## 1. 每次执行先判断

自举完成后执行 `node scripts/workday.mjs`，读它输出的**纯 JSON**：

| 字段 | 含义 |
|---|---|
| `skip` | true = 周末 / 法定假期 / 非工作日 |
| `reason` | 跳过原因（周六、周日、法定放假日），收尾如实写明 |
| `latestIssue` | 已出刊的最新一期日期 |
| `catchUpDays` / `catchUpDates` | 上一期之后到今天之前被跳过的日期 |
| `searchFrom` | 本次搜索窗口起点 |
| `windowLabel` | 补窗区间，仅供自检 |
| `calendarWarning` | 该年节假日未维护时提示补 `holidays.json`，仍按周末判断 |

## 2. skip = true：直接结束

**不搜索、不写 `content/`、不出刊、不发布、不构建、不改页面、不补空白期。**
收尾只回复「今日非工作日（reason），按规则跳过」。`skip` 是正常结束，不是失败，不要触发兜底补跑、不要重试、不要谎报"今日期次未就绪"。
站点同步任务同理：非工作日直接结束，不构建不发布。

## 3. skip = false：只放宽搜索窗口

- `catchUpDays = 0`：与平常**完全一样**，只检索当天或过去 24 小时。
- `catchUpDays > 0`：把搜索窗口从「过去 24 小时」扩展到 **`searchFrom` 起至今天**，逐日检索 `catchUpDates` 里的每个跳过日期，把这几天够格、够重要的硬新闻一并纳入本期素材池。`windowLabel` 用来核对有没有漏掉某一天。

## 4. 除搜索窗口外，一切照旧（硬约束）

读者明确要求「不要改变结构，仅仅是拓展搜索窗口就行了，别的都是一样的」。所以：

- **不变**：选题标准（`source-guide.md` 第二条，含网上舆情讨论度与社会新闻宽松）、财经/非财经配比、每条 `why`、小水花黑名单、四个重点与完整专题、深挖、属地新闻、`synthesis` 写法与统计口径、发布流程、内容包结构、所有字段与版面结构。
- **不做**：不新建期次、不补写跳过日期的空白期、不加「假期汇总」模块、不给条目加日期徽标或特殊标签、不因为"要补几天"而多收条目。
- 多天素材**按同一把重要性尺子挑**，够格才收，宁缺毋滥；`synthesis` 里可以自然带到"这几天发生了什么"，但格式与平常一致，不写成流水账。
- 事实核实不变：所有条目仍须回溯 A/B 层，日期以原文为准，禁止把旧闻当今日新闻，禁止把几天前的传闻当已核实事实。

## 5. 日历维护

每年国务院公布次年放假安排后，只改 `content/holidays.json`：把放假区间补进 `holidayRanges`、调休补班日补进 `makeupWorkdays`、年份加进 `coveredYears`。脚本会自动展开区间，不需要改定时任务、不需要改代码。
