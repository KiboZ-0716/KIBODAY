# AI 周报提示词 · weekly-brief

> 版本：v2.0
> 产出：`content/weekly/<ISO 周>.json` → 管线编成 `src/data/weekly.json`
> 定位：K!B0 的第二本刊物。读者是**要拿它做决策的产品经理与项目经理**，不是看热闹的人。
> 一句话原则：**周报不是把日报标题换个说法重发一遍**。日报回答「今天发生了什么」，周报回答「这一周哪个变量变了、它怎么一步步传导到我的立项、报价与验收」。
> 信源前置规范：`content/prompts/source-guide.md`。禁止政务通稿、会议开幕、表彰、榜单揭晓、工程进度播报凑数；事实主体须来自公司公告/财报/官方博客/监管文件/机构报告（A 层）或财新、第一财经、晚点、路透、彭博、The Information、Ars Technica、BleepingComputer 等权威媒体（B 层）。

## 一、收录范围与时间窗

- 时间窗：过去 7 天（周五发稿，覆盖上周五至本周四）。
- 主题：AI 行业的产品、模型与研究、开发者工具与开源、算力与芯片、资本与财报、政策治理、安全事件、应用与商业化。
- 每条事实要有公开来源（名称 + 日期 + 链接）；同一事实有两个以上独立来源时优先采用。
- **窗口外事件只能作「背景」**：必须在正文里写明具体日期并标注「背景」，不得混入本周事实，不得靠它撑篇幅。
- **不与日报复读**：不得把当日日报的宏观新闻（CPI、进出口、成品油、展会等）搬进周报凑数；不得把日报标题换个措辞当成周报条目。周报的事实要能独立成立。

## 二、广度（硬约束，出刊闸门会查）

- 每期 **3—5 条深读**，且必须**跨至少 4 个不同赛道**。赛道清单：
  1. 资本与单位经济学　2. 算力、芯片与能源　3. 开发者工具、框架与开源　4. 治理、合规与内容责任
  5. 模型、研究与评测　6. 安全、凭证与供应链　7. 政企采购与应用落地　8. 国际大厂与竞争格局
- 禁止整期扎堆在一个方向（例如全是中国宏观 / 全是算力 / 全是合规）。**同赛道最多 1 条深读**。
- 「本周发布速览」只收**可清点的**产品、版本、报告、标准、清单、融资，**8—12 项**，且**不得与深读条目重复**。
  收「豆包月活 4.19 亿」这类有口径的数据可以，收「10 月 CPI」「进博会闭幕」这类非 AI 宏观新闻凑数不可以。
- overview.chips 要能反映本期覆盖的多个赛道，不是同一个话题的近义词。

## 三、深度（硬约束，v2 结构，出刊闸门会查）

每条深读除了 `fact / analysis / pm / project / action / sources`，**必须填齐以下字段**，缺一个编排就报错：

| 字段 | 写什么 | 反例（会被拦） |
|---|---|---|
| `bottomLine` | 2—3 条结论，最后一条是「判断：」开头的判断句 | 把标题拆成三句复述 |
| `fact` | 发生了什么：时间、机构、可核对数字；事实与判断分开，不写「据 XX 报道」导语 | 只有标题级信息 |
| `analysis` | 判断链：为什么会这样、影响落到谁；≥60 字 | 「值得关注」「意义重大」式一句口号 |
| `context` | 前因：此前什么状态、触发点是什么、时间线 | 复述 fact |
| `mechanism` | 机制：从触发到结果怎么一步步传导，用「→」写清链条；≥60 字 | 只写结论不写过程 |
| `keyNumbers` | 3—5 个带口径数字，每个含 `value / label / note`；note 写清谁发布、统计什么、不含什么、是否预测、不能外推成什么 | 光列数字不写口径 |
| `concept` | 概念与口径辨析：解释一个行话，说清两个易混口径的区别 | 名词解释凑字 |
| `stances` | 2—3 条各方说法（厂商 / 买方 / 监管 / 存疑一方），每条含 `source / point` | 全是同一个立场的三句话 |
| `openQuestions` | 2—3 个待解问题：现在公开信息里还缺什么 | 「后续值得观察」 |
| `watch` | 下一步盯什么：具体的文件、数据、日期、可验证节点 | 「持续关注进展」 |
| `pm` / `project` | 分别给两个角色的结论，**具体到能照做**，不写「把 X 写进 SLA/检查表」这类能互换的套话 | 放之四海皆准的祈使句 |
| `action` | 本周可以做的一个动作，含对象、数量或验收标准 | 「加强重视」 |
| `sources` | 2—4 条 A/B 层来源，含 `name / date / url` | 聚合号「XX 合集」「XX 热点汇总」 |

## 四、总览、趋势、清单（避免口水的三处重灾区）

- `headline` / `thesis`：写**结构性判断**（哪个变量变了、为什么），不做事件罗列。
- `overview.copy`：一段 150—250 字的综述，讲清本周几条主线互相怎么咬合；不要罗列数字。
- `overview.numbers`：3—4 个数字，`label` 必须带口径或边界（如「累计清理，非本周新增」「链路时延，非端到端」）。
- `trends`：2—3 条，每条 `body` ≥90 字，必须写全 **依据 + 反例/证伪条件 + 可验证的观察点**。
  页面已标注「观点 · 非事实」，**不要再写「这是观点不是事实：」这种前缀**，直接给判断和依据。
- `checklists`：产品经理、项目经理各 4 条，每条含**对象 + 动作 + 验收标准**，不写通用套话。

## 五、语气与禁忌

- 不用「颠覆」「革命」「史诗级」「赋能」「重塑」「值得关注」「引发热议」；不预测股价、不给投资建议。
- 数字必须带口径与时间；不写「大幅」「显著」这类无法核对的程度词。
- 判断句以「判断：」开头并说明依据；事实与判断严格分开。
- 不编造。涉及未公开信息、单一匿名信源、无法核实的数据，一律写「尚未披露」并放进 `openQuestions`。

## 六、写稿前自检（逐条过，任一不过就重写）

1. 深读是否跨了 ≥4 个赛道？有没有两条其实在讲同一件事？
2. 每条深读的 `mechanism` 有没有写出「→」传导链，还是只有结论？
3. 每个数字有没有写清口径、不含什么、能不能外推？
4. `stances` 里有没有真正的反方或存疑一方，还是三句话一个立场？
5. `openQuestions` 是不是具体的信息缺口，而不是「后续观察」？
6. `watch` 有没有具体到某份文件、某次发布、某个日期？
7. `shipList` 有没有混入非 AI 宏观新闻凑数？有没有和深读重复？
8. `trends` 有没有反例与可证伪条件？
9. `pm / project / action` 换个事件还成不成立？成立就是套话，重写。
10. 有没有把当日日报标题换个说法当成周报内容？
11. 窗口外事件是否都标了日期和「背景」？

## 七、字段清单（缺字段编排会报错）

```
id / no / label / period / publishedAt / schemaVersion(=2)
headline / thesis
overview { copy, chips[4-6], takeaway, numbers[3-4]{value,label} }
deepDives[3-5] { no, category, title, fact, analysis, bottomLine[2-3], context, mechanism,
                 keyNumbers[3-5]{value,label,note}, concept, stances[2-3]{source,point},
                 openQuestions[2-3], watch, pm, project, action, sources[2-4]{name,date,url} }
shipList[8-12] { name, category, meaning, heat }
trends[2-3] { title, body }
checklists { pm[4], project[4] }
method / sources[{name,date,url}]
```
